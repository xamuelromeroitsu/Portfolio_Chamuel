# Internacionalización (i18n)

Documentación de la estrategia de internacionalización del portafolio: español, inglés y portugués.

> **Estado actual:** la aplicación ya consume i18n. Están implementadas las rutas `/es/`, `/en/` y `/pt/`, la traducción de la interfaz, los proyectos desde el catálogo local, el formulario, las shells SEO y los redirects de Vercel. **No hay selector de idioma visual:** el idioma se determina por la URL. Pendiente: dominio final, variante de portugués, anti-spam y prueba de despliegue en Vercel Preview.

## 1. Decisiones

| Tema | Decisión | Motivo |
|---|---|---|
| Idiomas | `es`, `en`, `pt` | Cobertura del portafolio |
| Idioma por defecto | `es` | Contenido fuente y fallback |
| URLs | `/es/`, `/en/`, `/pt/` | SEO, `hreflang` y enlaces compartibles |
| Raíz `/` | Redirección 301 a `/es/` | Evitar contenido duplicado |
| Secciones | Anclas por idioma: `/en/#contacto` | El sitio es una sola página |
| Traducción | Interfaz, proyectos y formulario | Traducción total |
| Librería | `react-i18next` | Integración con React y hooks |
| Mensaje libre | No se traduce | Se envía tal como lo escribió el visitante |
| Correo del admin | Siempre en español | El propietario lo lee; se incluye el idioma original |
| SEO | Shells HTML por idioma | `lang`, title, description, canonical y `hreflang` sin SSR |
| Fuente del idioma | La URL | No se usa `localStorage` para decidir el idioma |
| Selector visual | No implementado | Decisión del usuario; el idioma se cambia editando la URL |

## 2. Dependencias

Instaladas en `package.json`:

| Paquete | Versión | Para qué |
|---|---:|---|
| `i18next` | `^26.5.11` | Motor de traducciones, interpolación y plurales |
| `react-i18next` | `^17.1.9` | `useTranslation`, `t` y cambio de idioma en React |
| `react-router-dom` | `^7.18.4` | Rutas `/es/`, `/en/`, `/pt/`, redirecciones |

**No instalar por ahora:**

- `i18next-browser-languagedetector`: la URL es la fuente de verdad.
- `i18next-http-backend`: los JSON son locales y Vite los importa.
- `react-helmet-async`: el SEO se resuelve con shells HTML.
- `react-intl`: duplicaría la librería elegida.
- Vike, Next u otro framework SSR: solo si se quiere HTML con cuerpo renderizado.

## 4. Configuración

### `src/i18n/languages.js`

Expone:

- `DEFAULT_LANGUAGE = 'es'`.
- `LANGUAGES` con `code`, `label`, `htmlLang`, `ogLocale` y `dir`.
- `LANGUAGE_CODES`.
- `isSupportedLanguage(value)`.
- `getLanguageFromPath(pathname)`.
- `getLanguage(code)`.

```js
getLanguageFromPath('/en/');           // 'en'
getLanguageFromPath('/pt/#contacto');  // 'pt'
getLanguageFromPath('/');              // 'es'
getLanguageFromPath('/asignacion-01/');// 'es'
```

### `src/i18n/index.js`

- Importa `es.json`, `en.json` y `pt.json`.
- Inicializa i18next con `initReactI18next`.
- Usa `lng` según `window.location.pathname`; en Node usa `es`.
- Usa `fallbackLng: 'es'`, `supportedLngs` y `load: 'languageOnly'`.
- Desactiva el escape de interpolación porque React ya escapa.
- Actualiza `document.documentElement.lang` al iniciar y al cambiar idioma.
- Se importa una sola vez en `src/main.jsx`.

### Uso en componentes

```jsx
const { t, i18n } = useTranslation();
const lang = i18n.resolvedLanguage || 'es';

<h2>{t('projects.title')}</h2>
```

Para objetos:

```js
const copy = t(`projects.items.${project.id}`, {
  returnObjects: true,
  defaultValue: {}
});
```

Reglas:

- No usar títulos traducidos como IDs ni como `key`.
- No concatenar frases traducidas; usar interpolación.
- No traducir nombres propios, tecnologías, URLs ni emails.
- Las claves se mantienen en inglés y son estables.

## 5. Rutas

```text
/                  -> 301 /es/
/es/               -> español
/en/               -> English
/pt/               -> português
/:lang/projects/   -> página de proyectos vacía, con el fondo del sitio
/es/#contacto      -> sección de contacto
/en/#contacto
/pt/#contacto
/:lang/contact/    -> redirección a /:lang/#contacto
/asignacion-01/    -> página existente, sin prefijo de idioma
```

### `src/main.jsx`

```jsx
<BrowserRouter>
  <Routes>
    <Route path="/" element={<Navigate to="/es/" replace />} />
    <Route
      path="/:lang"
      element={
        <LanguageRoute>
          <ScrollToHash />
          <App />
        </LanguageRoute>
      }
    />
    <Route path="*" element={<Navigate to="/es/" replace />} />
  </Routes>
</BrowserRouter>
```

### `LanguageRoute`

- Valida `lang`.
- Cambia i18n si no coincide con la URL.
- Actualiza `document.documentElement.lang`.
- Actualiza `title` y `meta description`.
- Redirige idiomas no soportados a `/es/`.

### `ScrollToHash`

- Lee `useLocation().hash`.
- Hace `scrollIntoView` al elemento correspondiente.
- Usa `requestAnimationFrame` y limpia el frame al desmontar.
- Los IDs `#inicio`, `#proyectos`, `#contacto` y `#contenido` no se traducen.

### Sin selector de idioma

No existe `LanguageSwitcher` ni botón de idioma. Para cambiar de idioma se navega a `/es/`, `/en/` o `/pt/` editando la URL. Los enlaces internos construyen la ruta con `i18n.resolvedLanguage`.

| Código | Español | English | Português |

| `freelance` | Proyecto freelance | Freelance project | Projeto freelance |

### Esquema y UI

`contactSchema.js` usa códigos de materia y claves de error:

```js
z.string().trim().min(2, 'contact.errors.name')
z.string().trim().email('contact.errors.email')
z.enum(CONTACT_SUBJECTS, {
  errorMap: () => ({ message: 'contact.errors.subject' })
})
z.string().trim().min(10, 'contact.errors.message')
```

`ContactForm` traduce el mensaje:

```jsx
const errorText = (message) => (message ? t(message) : null);
```

### Servicio

`ContactServiceError` conserva solo el código:

```js
export class ContactServiceError extends Error {
  constructor(code, cause) {
    super(code, { cause });
    this.name = 'ContactServiceError';
    this.code = code;
  }
}
```

La UI traduce `t(\`contact.errors.${error.code}\`)`.

Códigos actuales:

- `configuration`
- `rateLimit`
- `unavailable`
- `delivery`
- `autoresponder`

### Parámetros de EmailJS

El mensaje libre no se traduce. El correo del administrador se mantiene en español:

```js
{
  name,
  email,
  subjectCode,
  subjectLabel,     // idioma del visitante, para la autorespuesta
  subjectLabelEs,   // siempre español, para el admin
  language,
  message,          // texto original del visitante
  to_email: email
}
```

Plantillas:

- Admin: usar `subjectLabelEs`, `message`, `name`, `email`, `language`.
- Autorespuesta: usar `subjectLabel` y `message`.
- Si se quiere autorespuesta traducida, crear tres plantillas o elegir según `language`.

## 8. SEO

### Shells por idioma

`npm run build` ejecuta `postbuild` y genera:

```text
dist/es/index.html
dist/en/index.html
dist/pt/index.html
```

Cada shell incluye:

- `<html lang="es|en|pt">`.
- `title` y `meta description` del locale.
- `canonical` propio.
- `hreflang` para los tres idiomas.
- `x-default` apuntando a `/es/`.
- Open Graph, Twitter Card y `og:locale`.

Con `SITE_URL` también genera `dist/sitemap.xml` y `dist/robots.txt`.

### Script de build

`scripts/build-language-shells.mjs`:

1. Lee `dist/index.html`.
2. Lee `meta` de `src/i18n/locales/*.json`.
3. Reemplaza `lang`, title y description.
4. Inserta canonical, `hreflang`, Open Graph y Twitter si hay `SITE_URL`.
5. Escribe las tres shells.
6. Genera sitemap y robots si hay `SITE_URL`.

Sin `SITE_URL` las shells se generan igual, pero sin canonical, `hreflang`, sitemap ni robots. No se publican placeholders.

```bash
SITE_URL=https://midominio.com npm run build
```

En PowerShell:

```powershell
$env:SITE_URL='https://midominio.com'; npm run build; Remove-Item Env:SITE_URL
```

### Vercel

`vercel.json` incluye:

- Redirect permanente de `/` a `/es/`.
- Rewrites de `/es/...`, `/en/...` y `/pt/...` a sus shells de idioma.

Los destinos son relativos a `outputDirectory` (`dist`):

```json
{ "src": "/es/(.*)", "dest": "/es/index.html" }
```

El redirect usa `statusCode: 301` (con `permanent: true` Vercel responde 308). Verificar el comportamiento en Vercel Preview.

### Limitación

Las shells corrigen `lang`, meta y `hreflang`, pero el cuerpo principal sigue renderizándose con React. Para SEO completo con contenido inicial renderizado habría que migrar a SSG/SSR. Para un portafolio, las shells son un buen equilibrio.

## 13. Cómo añadir otro idioma

1. Añadir el idioma a `LANGUAGES` en `languages.js`.
2. Crear `src/i18n/locales/<code>.json` con la misma forma que `es.json`.
3. Importarlo y añadirlo a `resources` en `index.js`.
4. Añadir la ruta, shell SEO y `hreflang`.
5. Actualizar tests y probar las URLs.
